A. ROOT CAUSE

The reported failure pattern is reproducible with the explicit LEGACY Electric
profile, not with the current October profile at the inspected Git HEAD.

In reference_files/RoboSprayer_8500Kg_Electric_02_UoL_Drive_Cycle_20kph_DriverPC_Flat_02.csv,
all four DriveShaft_Torque_FL/FR/RL/RR arrays are exactly zero across 2,197
samples. The four KERS_MotGenUnit_GearboxOutputTorque_1..4 arrays are active.
Their initial values include 8,115.03, 8,115.59, 8,764.91 and 8,765.12 Nm.
The legacy configuration explicitly requests DriveShaft_Torque_*. Resolution
therefore selects valid, inactive signals and its wheel power is zero.
This is configuration selection, not an activity-based alias choice, importer
unit conversion, or Excel/PowerPoint corruption.

Current profiles in config/report_profiles/sergio_2026_10 explicitly override
the four sources to KERS_MotGenUnit_GearboxOutputTorque_1..4, with empty alias
lists. Missing sources disable dependent results; shafts are not substituted.
The UI already defaults to these current profiles. The base profiles remain
explicit legacy definitions. Loading a base YAML directly also selects legacy
behavior. Shared semantic IDs named driveshaft_torque_* do not determine the
physical source: inspect source_name in the profile and report mapping sheet.

Physical meanings and units:
- DriveShaft torque [Nm] is a distinct measured shaft channel, which may be
  inactive for a particular VSM driveline architecture.
- Motor/EDU torque [Nm] and speed [rpm] are ElectricSystem_EM1..4 measurements.
  Mechanical EDU power [kW] = motor torque * motor rpm * 2*pi/60000.
  Electrical EDU power channels remain separate electrical quantities.
- KERS gearbox-output torque [Nm] is measured downstream of the motor gearbox.
  The current client templates explicitly identify it as their Wheel Torque.
- Configured wheel power [kW] = corresponding gearbox-output torque * measured
  wheel rpm * 2*pi/60000. Signed torque, speed and regenerative power are retained.
- Wheel Total Torque sums four signed torques. Wheel Power Total sums four
  simultaneous corner powers, not four independently located maxima.

The 8,500 kg CSV provides additional evidence for this shaft pairing: median
motor/wheel speed ratio is approximately 17 and median motoring output/input
mechanical power ratio approximately 0.97 at every corner. Median output/motor
torque ratio is approximately 16.49. These are DATA INFERENCES, not newly entered
model parameters. Motor-versus-17*wheel speed residuals reach 0.3603 rpm and
motoring torque-versus-16.49*motor residuals reach 0.05032 Nm. Finite-resolution
exports and differing measurement locations/transient samples prevent treating
these relations as exact throughout the trace. No ratio or efficiency is applied
again to measured gearbox torque, and no torque is reconstructed from motor data.

The authoritative report definition is the client workbook mapping and formula,
supported by measured speeds. The repository does not contain the VSM mechanical
model or a manufacturer topology specification. This is not a universal claim
that any gearbox output on any future configuration is net tyre/contact torque.
Different downstream gearing needs its own explicit configuration and authority.

Keeping existing source definitions and exact SI calculations is preferable to
globally replacing legacy mappings, selecting whichever signal is nonzero,
adding shaft aliases, guessing gear ratios, or fabricating motor-derived torque.
Raw channels and MATH channels stay distinguishable in import metadata, workbook
mapping, formulas and report provenance. Separate Hybrid driveshaft torque-map
inputs remain available and never feed the current gearbox-based power equations.

   11.03 kW / 635 rpm / 218.23 Nm maxima cannot be numerically reconstructed.

assertion. When capturing logs in PowerShell, use:
  python <arguments> *> <log>; $torqueExit = $LASTEXITCODE; exit $torqueExit
