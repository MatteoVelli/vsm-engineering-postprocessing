Confirmed root causes (references refer to current files unless marked before)
---------------------------------------------------------------------------
1. Configuration matching, not missing rear-hitch data, suppresses 8500 capacity.
   config/report_profiles/robosprayer_electric.yaml:9 defines the 3500 mapping,
   with RoboSprayer/RoboSprayer V5 names and a supported inferred-load flag.
   The 8500 entry at line 21 accepts Full Size/Full Size Sprayer, not RoboSprayer.
   report_metadata.py:98-109 matches name AND powertrain AND identity tokens.
   Consequently RoboSprayer_8500Kg_Electric remains unmatched, with default
   hitch_force_is_remaining_agro_mass=False. A present channel does not establish
   its physical meaning. No alias was added that would automatically confirm it.

2. Agro Capacity and kg/km are separate reporting calculations by design.
   agro_reporting.py:113 gates capacity on the physical-interpretation flag.
   It computes the observed maximum -Fz/9.81 only when that flag is supported.
   calculate_net_mass_discharge_rate(), line 43, checks numeric/unit/distance
   validity but does not accept or require that interpretation flag.
   calculate_reporting_kpis(), line 261, feeds it the preserved profile MATH
   channel agrochemical_discharge and cumulative track distance.
   excel_report_engine.py's summary registry substitutes the report-qualified
   capacity for the legacy maximum; the PPT agro cards use that same registry.
   This explains an N/A capacity alongside a nonzero calculated kg/km rate.

   Exact 3500 case: 3769 imported samples; initial inferred mass
   498.1569826707441 kg, final 11.25881753312946 kg, final distance 10.7392 km.
   Observed capacity = 498.1569826707441 kg.
   Net rate = 45.33840184907765 kg/km.

   Exact 8500 case: 2197 imported samples; initial profile mass
   3996.788990825688 kg, final 97.2960244648318 kg; final distance 10.7388 km.
   (3996.788990825688 - 97.2960244648318) / 10.7388
     = 363.1218540582613 kg/km, displayed as 363.12 kg/km.
   The unqualified status 'calculated' previously did not explain that numeric
   availability and physical validation are independent. The correction adds
   this qualification in the shared registry, Excel diagnostics, PPT and notes.
   No numeric expression or gravity constant was changed.

3. Electric static specification override.
   Before correction, robosprayer_electric.yaml:3063-3068 supplied metadata_pills:
     GVW 3,500 kg / Electric powertrain / 12 kph field /
     Battery 50 kW / Motor 63 rpm.
   _cover_metadata_items() previously returned any five configured pills before
   considering the current report. Both the cover and overview used that helper.
   This is a profile-level hard-code rather than a CSV or Excel calculation.
   The Astauto template contains the same strings, but the active renderer was
   actively reapplying them from YAML. Removing template text alone would fail.

4. Hybrid and Diesel findings.
   Hybrid's own presentation replaces the Electric presentation object
   (report_profile.py _merge_profiles: child.presentation or parent.presentation).
   Its metadata_pills are empty, so the specific Electric five-pill leak was not
   reproduced. Hybrid does inherit Electric/common numerical definitions and
   compatible machine configuration records; matching still checks powertrain.
   Diesel is independent and previously replaced the five pills with identity,
   source and sample fields in its own adapter. It did not reproduce this exact
   leak either. Both paths lacked a common representation of component ratings,
   missing-specification status and provenance. Both now use the shared resolver.
   Hybrid's observed generator maximum (80 kW) is a simulation statistic, not
   evidence of its generator rating. The shared component rating remains unset.

5. Manual UI state could cross source boundaries.
   ui_app.py _render_reporting_metadata_inputs previously keyed battery mass
   only by powertrain, and advanced override widgets had no source scope. A
   manual value could survive switching to another CSV with the same profile.
   All these widgets now include source path/revision and profile in their key.
   The validation identity now always includes the machine display name.

6. Explicit configuration and speaker-note gaps.
   An explicitly requested configuration previously bypassed identity tokens,
   permitting a 3500 configuration on an 8500 filename sharing the same name.
   Explicit requests now reject a contradictory filename mass token.
   Identity matching is restricted to tokens before the powertrain, preventing
   a later chemical-payload token (e.g. 3500Kg) from selecting a different vehicle.
   Electric/Hybrid previously rewrote notes on only the battery/agro pages;
   Diesel notes contained source/profile and selected numeric values only.
   Every generated slide now receives current source hash, machine, profile,
   configuration detection, specifications/provenance, reporting inputs, agro
   diagnostics, selected statistics and plot identifiers. Template notes cannot
   silently survive on an unmodified page. Display-name aliases produce an
   explicit source-identity warning; they do not rewrite simulation identity.

Corrections and configuration contract
-------------------------------------
machine_specifications.py is a small shared reporting-only module. A matched
machine_configurations record may have specifications for gvw_kg,
target_speed_kph, battery, motor, generator and engine. Each entry requires
value, status (confirmed/user_provided/estimated) and nonempty provenance.
Mass/speed have fixed kg/kph units and positive finite numeric values. Component
descriptions contain the supplied specification and its explicit units; no motor
count, voltage, battery energy, rating or generator size is synthesized.

Unconfigured components display Not specified. Filename mass/speed are retained
as filename_claim records and visibly labelled TBC. A filename's mass is called
Mass, not confirmed GVW: its physical meaning requires confirmation. Chemical
payload mass tokens after the powertrain are not mistaken for vehicle GVW.
Simulation maximum speed is still a measured KPI and is not used as target speed.
Measured battery power/energy/SOC and generator power are not component ratings.

The legacy metadata_pills schema is still readable for compatibility, but its
free-form strings are no longer a specification authority for profile reports.
Electric, Hybrid and Diesel covers/overviews all use the shared resolved metadata.
Excel Metadata and both report manifests store the same specification records,
configuration detection and warnings. Numerical channels, KPI expressions,
plot arrays, canonical values, gravity conventions and existing layouts remain.

Engineering assumptions requiring Sergio's confirmation
------------------------------------------------------
* Is RoboSprayer_8500Kg_Electric the same physical/model configuration as the
  Full Size 8500 mapping? Supply evidence before adding any equivalence/flag.
* For each source, does rear vertical hitch force isolate remaining agrochemical
  weight across the full operating window, including dynamic hitch reactions,
  implement tare, slopes, refills and sign conventions?
* Does 3500/8500/9300 in the filename mean GVW, curb mass, laden mass or another
  model parameter? Is 12/20 kph the approved target speed?
* Confirm battery mass (450/1000 are manual report inputs), rated energy, voltage,
  power, chemistry and pack configuration; motor number/type/rated power/speed;
  generator and engine ratings for the exact machine/simulation revision.
* No approved chemical density or calibrated volume/flow source was found.
  Volumetric discharge remains unavailable without its own provenance.
* An observed maximum inferred mass is not a nominal tank capacity. Tank volume,
  usable contents, refill segmentation and actual spraying phases need evidence.
* Caiman has negative inferred remaining contents; its full-window physical
  discharge and net kg/km are unavailable. A positive observed maximum does not
  repair that trace. The Diesel reference has all-zero hitch force: capacity is
  unavailable and the independent numerical kg/km result is zero.
* Electric/Hybrid's 85% usable-energy range convention and energy/SOC-derived
  nominal capacity remain model assumptions, not confirmed battery specifications.
  Diesel retains legacy g=9.80665 in the numerical mass channel while the separate
  report-qualified inferred capacity uses g=9.81. Both are recorded, not unified.
* October and legacy profiles intentionally use different auxiliary-energy and
  related mappings. Compare the same revision/selection; do not call those
  pre-existing differences numerical regressions from this reporting correction.
